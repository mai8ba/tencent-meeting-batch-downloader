## 2026-10-30 夜：v1.8.5 —— 上下文失效友好化 + 版本一致性自检 + 兼容垫片

### 现场
- `Extension context invalidated.` + 「待核对记录撤回失败」
- 更早还看到 `TMeetFiles is not defined`（batch.js:644）

### 三条结论
1. **`Extension context invalidated.`** = 扩展被 ⟳ 重载，页面里旧 content script 的上下文**当场作废**。
   用户在导出跑到一半时按了 ⟳，于是导出被打断、"待核对"撤回也失败。**不是 bug，是操作时序。**
2. **`TMeetFiles is not defined`**：磁盘上的 `batch.js` 早已零引用（第二轮就删干净了），
   截图里的堆栈行号 642/643/644 与当前源码逐行吻合 ⇒ 是 **Chrome 累积保存的历史错误**，
   `chrome://extensions` 的错误页会把旧错误一直留着，不是当前错误。
3. `TypeError: ... null (reading 'addEventListener')` 同理：旧版 `bind()` 没有 `?.` 保护留下的历史记录。

### 这轮的改动
- **上下文失效友好化**：`rpc()` 捕获 `Extension context invalidated` /
  `Could not establish connection` / `message port closed`，翻译成
  「扩展刚刚被重新加载，页面里的插件已失效。请按 F5 刷新本页后继续（已导出的文件不受影响）」。
- **脚本版本一致性自检**：`batch.js` 声明 `BATCH_JS_VERSION` 并暴露给外壳；
  `panel.js` 比对「运行中的脚本版本」与「扩展版本」，不一致时状态灯报红并写明
  「工作台脚本是旧版（vX），扩展是 vY：请在扩展页点 ⟳ 重新加载，再按 F5 刷新本页」。
  宿主属性 `data-tmeet-js-version` 也能在页面控制台直接读出来。
- **兼容垫片 `compat.js`**（manifest 里排第一）：面板跑在 content script 隔离世界里，
  `TMeetFiles` 这类全局只在扩展页（`<script src="local-files.js">`）里存在。
  垫片给出降级实现，"旧脚本配新页面"时不再整个面板因 ReferenceError 瘫掉。
- **导出期现场提醒**：进度条下方常驻「导出期间请不要重新加载扩展或刷新本页」。
- 版本号升 **1.8.5**（manifest / HTML 戳 / 脚本常量 三处一致，有测试守着）。

## 2026-10-30 夜：定位「更多菜单未找到导出」——录制页当时不在前台

### 用户的现场诊断（决定性）
```
{"step":"menu.not-found","matched":0,"visible":0,"pageHidden":true,
 "visibleMenu":[{"text":"中文","cls":"met-dropdown.met-select"},
                {"text":"30","cls":"met-dropdown.met-select"},
                {"text":"我的会议个人资料…","cls":"met-menu__list"}], "other":[]}
```
- `pageHidden: true` → **录制页处于隐藏状态**（标签页在后台 / 窗口最小化）
- `matched: 0` + `visibleMenu` 里全是页面其他下拉（语言「中文」、每页「30」、顶部导航），
  **一个菜单项都没有** → 菜单压根没弹出来，不是"文案变了"

### 根因
腾讯会议的「更多」菜单是 **hover 才渲染**的（DOM 里平时就不存在「导出」这一项）。
页面不可见时 hover 根本不触发 ⇒ 菜单不弹 ⇒ 找不到「导出」；
同时后台标签页还会被 Chrome 节流、甚至 Memory Saver 冻结。
（"已确认完成 4"说明导出链路本身是通的，只有那一步碰上不可见。）

### 改法（三层）
1. **导出开始前**：录制页不可见 → 由后台 `focus-recording-tab` 把该标签页激活、
   窗口唤回（最小化的窗口一并恢复为 normal）。
2. **导出中途被切走**：不再报错，而是**挂起等待** —— 进度条显示
   「导出已暂停：录制页不在前台（窗口最小化也算），切回「我的录制」就会自动继续」，
   切回来自动接着跑，进度不丢。
3. **报错文案**：菜单找不到时若当时不可见，补一句
   「（录制页当时不在前台，站点菜单不会弹出：请保持「我的录制」页面在前台再导出）」。

## 2026-10-30 夜：定位到真凶——「旧 JS + 新 HTML」混合状态（版本升到 1.8.4）

### 用户截图里的决定性线索
- 「更多」消失、「下载他人分享课程」直接显示 → **`batch.html` 是新的**
- 标题栏没有版本号 → **`panel.js` 是旧的**
- 状态行停在「正在连接录制目录…」、badge 停在「检查授权…」 → **`init()` 压根没执行**

### 两个机制
**① `batch.html` 是 `fetch` 出来的** —— Chrome 实时读磁盘 ⇒ 永远最新；
**`panel.js` / `batch.js` 是打包进扩展的代码** —— **只有 ⟳ 重载才更新**。
所以「只按 F5 不按 ⟳」会得到**旧 JS + 新 HTML** 的混合状态：
界面长得对（HTML 新），但所有行为都是旧的（JS 旧）。

**② 旧代码的 init 依赖 `document.readyState`**
面板模式 `await` 完面板资源后若 readyState 仍是 `'loading'`，就去等 `DOMContentLoaded`；
腾讯会议是重 SPA，那个事件可能迟迟不来 ⇒ init 永不执行 ⇒
界面停在初始文案，而**所有按钮的 onclick 都在 init 里的 bind()** ⇒ 点了全无反应。

### 这轮的根治
- **面板启动改由外壳显式叫醒**：`panel.js` 铺好 DOM 后调 `batch.js` 的 `__tmeetBatchInit`（幂等），
  不再猜 readyState；batch.js 侧保留 1 秒兜底自启（防外壳是旧版）。
- **标题栏启动状态灯**：启动中… / 已就绪 / 启动失败 / 待重载，一眼可辨。
- **版本号上标题栏**（v1.8.4）+ 宿主 `data-tmeet-stage` / `data-tmeet-version`（主世界也能查）。
- **版本戳自检**：`batch.html` 的 `#tmeet-build` 与 manifest 版本比对，
  不一致直接红字提示「请在扩展页点 ⟳ 重新加载，再按 F5 刷新本页」。
- **版本号升 1.8.4**：`chrome://extensions` 能一眼确认加载的是不是新代码。

## 2026-10-30 夜：按钮全部改成事件委托（根治"整面板点了没反应"）

### 现场
上一轮加了 `assertDom()` 之后，用户仍报「点打开录制主页无反应、点采集清单无反应」。
实测确认：**布局没有遮挡**（`elementFromPoint` 三个 .step 按钮命中的都是内部的 `<strong>`，
点击照常冒泡），说明问题不在样式层，而在**事件到底有没有绑上**。

### 根因
`bind()` 里是逐条 `$('id').onclick = …`。**只要有一条取不到元素就抛 TypeError，
后面全部不会执行**。上一轮加的 `assertDom()` 反而更糟——它挡在 bind 前面，
一旦结构对不上，连 bind 都不会跑，等于把"部分按钮失效"升级成"全部失效"。

### 改法（结构性）
- **整张「id → 动作」表 + 影子根上唯一一次 click 委托（捕获阶段）**；
  任何一个元素缺失只影响它自己，其它按钮照常可用；
- 委托**挂在 bind 最开头**（`clickActions` 声明之后），排在任何可能抛异常的语句之前；
- `assertDom()` 降级为纯诊断（只 `console.warn`），再也不挡在 bind 前面；
- 类型筛选（无 id，用 `data-type`）与搜索框 `input` 也走委托；
- **标题栏显示版本号 `v1.8.3`**：用户截图即可确认加载的是不是新代码
  （"改了没生效"多半是扩展没重载 / 页面没 F5）。

### 验证
- **真实鼠标坐标点击**（CDP `Input.dispatchMouseEvent`，不是 JS `.click()`）：
  点第 1 步 → toast「已连接录制目录」；点采集清单 → toast「开始采集」+ 采集到 1 项。
  这一条很关键：之前只测过 `element.click()`，它绕过命中测试，测不出遮挡。
- 单元 209 项（207 过 / 2 skip），panel.test.cjs 加"禁止裸 onclick"回归锁（10 项）

## 2026-10-30 晚：修「点第 1 步卡死」+「更多」菜单下线

### 现场
点第 1 步「打开录制主页」毫无反应，界面停在全套初始文案（连 badge 的「检查授权…」都不变）。

### 两个独立根因

**① bind() 被一个缺失元素整段打断（静默失效）**
`bind()` 全是 `$('id').onclick = …` 这种写法，任何一次取不到元素就抛 `TypeError`，
**后面所有按钮统统不绑定**，界面从此完全没反应，控制台之外没有任何痕迹。
最常见的触发场景：重载扩展（⟳）后没按 F5 —— 页面里跑的还是旧 batch.js，
它去找已经被删掉的 `btnPickDir`，当场断。

**② 面板模式下"打开录制主页"会让后台 reload 当前页**
`open-recordings` 会 ping 各录制页，挑不到"活着"的就 `chrome.tabs.reload()`。
而面板脚本就住在这个页面里 —— reload 等于把刚点按钮的面板自己销毁了。

### 改法
- `assertDom()`：bind 之前先核 30 个必需元素，缺了当场报出名字；
- `reportBootError()`：初始化任何一步失败都写到顶部状态行 + badge 变红，
  不再"只在控制台躺着"；`render` / 首次同步失败也不再阻断后面的定时刷新；
- **第 1 步分流**：`inPanel()` 时只做本地 `refresh()` 重连（toast 直说"已连接/请按 F5"），
  `open-recordings` 只留给独立页模式；面板里文案同步改成「连接录制目录」。
- **「更多」菜单整体下线**：`下载他人分享课程` 直接放顶栏（普通按钮，一眼可见）；
  `全量校验 / 续导`、`清空本地清单` 一并移除；`复制诊断信息`不占位置——
  **点顶部状态行即可复制**。

- 轻量兜底：逐字稿 < 5KB 时在结果里提示「可能只生成了标题」，但**不判失败**、不阻塞。

## 自动测试（2026-10-30 中午，调试期，未改版本号）

### 用户反馈：点「开始导出」毫无反应

**根因是两处叠加，都会让点击彻底静默：**

1. `btnExport` / `btnStop` 在 HTML 里初始就带 `disabled` 属性 ——
   **disabled 的按钮收不到 click 事件**，浏览器直接吞掉点击，连处理器都不进。
2. 处理器第一行是 `if (state.starting || state.busy) return;` —— 静默返回，
   没有任何提示。一旦中间态卡住（扩展重载/录制页失联导致消息没回来），
   按钮就永远点不动，用户无从判断该先做哪一步。

**改法（原则：点击永远有反馈）：**

- 全部按钮**弃用 `disabled` 属性**，改用 `aria-disabled` + `.is-blocked` 表达状态；
  `setBlocked()` 里显式 `btn.disabled = false`，杜绝它再被写回来。
- 新增 `whyCannotExport()` / `whyCannotCollect()`：把"为什么点不了"写成一句能照做的话，
  点击时直接弹出来（例如"请先点第 2 步「选择文件夹」并授权（只需一次）"）。
- 停止按钮空闲时点了也说话（"当前没有运行中的任务"）。
- **看门狗**：`starting` 中间态超过 45 秒自动放行，并提示"请刷新「我的录制」页面后重试"。
- 更多菜单新增**「复制诊断信息」**：一键复制 connected / busy / starting / dir / live /
  cannotExport 等现场，用户贴过来即可定位，不用来回截图。

**回归锁**（e2e-flow 新增 5 项）：按钮不使用 disabled、没勾选时点导出必须弹原因、
点不了的按钮用 aria-disabled 但点击仍有效、空闲时点停止也要有提示、进度条不显示假的"正在校验"。



### 用户截图暴露的问题：点开始导出立刻失败

截图里右上角写着「**无法恢复采集时的每页条数**；已确认完成 0，失败 0，待核对 0」——
导出在**第一项都没开始**时就整批中止了。

根因：`setPageSize()` 注释写着"只比数字"，代码却是整串精确匹配 `(li.innerText||'').trim() === String(size)`。
站点每页条数的选项常带单位（"30 条/页"），一旦带单位就永远匹配不上 → 设置失败 → 导出中止。
（当时站点恰好已经是 30 条/页，采集阶段直接命中 "current === size" 走了捷径，所以采集没事、导出才炸。）

修法：

1. `firstNumber()` 统一按数字读：`"30"`、`"30 条/页"`、`"每页 30 条"` 都读出 30；
2. 下拉已经展开时**不再点表头**（那会把选项收起来，之前就是这么把自己绕进去的）；
3. **设置失败不再整批停**：读得出当前条数就按绝对序号换算页码（`rebasePages`）继续导出，

### 这轮自动测出并修掉的三个问题

1. **采集/导出结束后界面永久卡在"任务运行中"**
   - 现象：采集完「采集」一直灰、点筛选只弹"任务运行中，先停止再改筛选"。
   - 根因：content 先 `setLive({phase:'done'})`、后清 `state.collecting`；工作台收到 done 立刻

2. **录制页开着却显示"没打开"**

   - 修法：background `open-recordings` 先用 `tmeet.ping` 找活着的标签页；全是失联的话顺手

## 本轮修复（现象：点了导出，一项都没下载）
